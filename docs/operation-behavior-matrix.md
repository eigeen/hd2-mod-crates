# 桌面端与 Web 端操作行为矩阵

基线日期：2026-09-05。本文记录重构前可从源码确认的行为，并把两端统一后的验收规则写成可执行条目。`目前实现` 不是目标契约；实现变化后应同步更新状态和对应测试。

## 共用约定

| 项目 | 期望行为 | 目前实现 | 验收方式 |
| --- | --- | --- | --- |
| Patch 分组 | 宿主只负责发现可访问文件；共享规则按主文件名和 `.gpu_resources`、`.stream` 分组，后缀匹配不区分大小写。迁移、修复一次接收一个 Patch，两个合并操作一次可接收多个 Patch。目录杂项不应被当成主文件。 | Web 合并使用后缀白名单并按文件名分组；Web 迁移和桌面把“不是 sidecar”的文件当主文件，桌面目录中出现多个候选会直接拒绝。 | 前端契约测试同时向 Web/桌面规范化入口提交：多 Patch、大小写 sidecar、杂项、孤立 sidecar；断言得到相同记录或相同错误码。 |
| sidecar 校验 | Rust 根据 TOC 声明的范围校验 sidecar。缺文件与长度不足使用稳定、可读的错误结构；不需要数据的空 sidecar允许缺省。 | 桌面 `load_patch` 导入时校验并会查找相邻文件；Web 迁移入口校验，Web 头部合并候选识别阶段只读 TOC，合并导入路径没有完全复用同一入口。 | 小 fixture 分别覆盖不需要 sidecar、缺 GPU、GPU 截断、缺 stream、stream 截断；四个操作在两宿主得到相同错误码和关键字段。 |
| 任务结果 | 状态统一为准备、运行、取消中、成功、已取消、失败。取消是否生效以提交边界为准：提交前观察到取消时必须丢弃未交付结果；宿主已经确认文件提交成功时，成功优先于晚到的取消并正常记录报告。打开文件或保存对话框后由用户取消属于已取消或未开始，不显示失败。 | 迁移/修复和两种合并各管一套任务状态；合并中的普通结构化对象可能显示成 `[object Object]`。Web 合并为同步 WASM，界面不提供有效的运行中取消。 | 应用控制器或真实组件事件测试覆盖提交前取消、提交成功后的晚取消、保存目标取消、引擎错误、输出错误；断言状态、toast、报告和输出 sink 的提交次数，不只测试帮助函数。 |
| 输出比较 | 比较 ZIP 解包后的相对路径、文件顺序规则、每项内容 hash、空 sidecar 规则、摘要和警告。ZIP 时间戳及压缩元数据不参与一致性判断。 | 两端 writer 不同；已有测试未系统比较解包内容和归一化报告。 | 同一小 fixture 经 native/WASM、buffer/chunk sink 后解包，逐项比较路径和字节，并比较归一化摘要。 |

## 迁移

| 维度 | 期望行为 | 目前 Web | 目前桌面 | 可执行验收项 |
| --- | --- | --- | --- | --- |
| 输入 | 一个有效 Patch、可用游戏数据目录、至少一个已解析来源到目标的映射。两端都能选择单个或多个目标；资源预算只决定是否提示或拒绝本次任务。 | Web 关闭批量目标选择，并按映射数和预计输出大小限制任务。 | 桌面允许批量目标选择，没有同一资源预算提示。 | 对同一来源连续点击 A、B，再次点击 B：两端分别得到 `[A, B]`、`[A]`；超过预算时业务映射不变，仅资源策略结果不同。 |
| 默认参数 | `singlePatch=false`，多个来源时强制单包；`noPadding=false`；未匹配 Unit 为 `keep`；Unit 行为开关采用 `emptyUnitBehavior()`；patch 文件名后缀为 `9ba626afa44a3aa3.patch_0`。 | 共享 workspace 使用这些默认值，但 Web 还要求多目标确认；请求由 Web 适配器再次组装。 | 共享 workspace 使用这些默认值，无多目标确认；请求由桌面适配器再次组装。 | 从初始页面事件一直捕获到引擎出口，断言两端编译出的 variants、`singlePatch` 结果、`noPadding`、未匹配策略、Unit 行为和后缀完全相同。 |
| 错误与取消 | 无游戏数据、无 Patch、无目标应在运行前阻止；格式错误、sidecar 错误、映射失败、资源不足、输出失败使用统一错误码。提交前取消不提交输出；已经确认提交成功时保留成功。保存目标取消不启动引擎。 | 主任务错误走 `presentTaskError`；WASM trap 可提示桌面版。浏览器下载只能确认已发起，不能确认落盘。 | Rust IPC 返回结构化 `CommandError`；保存对话框取消返回 `null`。协作取消可停止任务。 | 为每个失败点断言 `{code,message}` 可读且无 `[object Object]`；提交前取消时 sink 未提交且状态为 cancelled；提交成功后的晚取消仍为 succeeded 并记录报告；保存取消时引擎调用次数为 0。 |
| 输出 | 单映射使用 `uniqueOutputFilename`；多映射使用 `hd2-migrated-patch.zip`。分包时每个目标目录包含 TOC/GPU/stream；单包时覆盖顺序稳定。摘要包含迁移数、警告数和逐项报告。 | Blob ZIP 下载；文件名函数和后缀常量位于 Web 适配器。 | 临时 ZIP 完成后提交到用户选择路径；同一文件名函数和后缀常量在桌面重复。并行进度标签可能与乱序完成项错位。 | 对单目标、多目标、多来源及冲突覆盖 fixture 比较解包内容、摘要和警告；并行打乱完成事件后输出顺序和 work item 标签仍稳定。 |

## Unit 修复

| 维度 | 期望行为 | 目前 Web | 目前桌面 | 可执行验收项 |
| --- | --- | --- | --- | --- |
| 输入 | 一个有效 Patch 和可用游戏数据目录。只更新 Patch 中的 Unit；没有 Unit 时成功并给出警告。 | 使用浏览器目录句柄和内存 Patch。 | 使用本地路径，导入时自动寻找邻接 sidecar。 | 同一无 Unit、小型旧 Unit、已是当前格式的 fixture 在两端得到相同计划与摘要。 |
| 默认参数 | 缺失 Unit 策略默认 `drop`。用户可明确选择 `drop`、`keep` 或 `fail`，选择值直接进入共享 Rust 用例。 | 默认 `drop`，运行前额外显示修复确认。 | 默认 `drop`，直接运行。 | 初始化断言为 `drop`；三种策略分别断言删除并警告、保留并警告、稳定排序的失败 ID 列表。两端请求必须相同。 |
| 错误与取消 | TOC 类型表损坏、资源数量不符、重复资源、游戏数据读取失败、输出失败使用统一错误码。提交前取消不提交输出，已确认提交成功时保留成功。 | 主任务错误走共享展示；WASM 仅在阶段回调处协作检查取消。 | IPC 使用 `repatch.failed`、`task.cancelled` 等结构化错误；保存取消返回 `null`。 | 仓库内 fixture 覆盖损坏类型 ID、数量不符和重复资源；两端断言同一错误码。提交前取消、提交后的晚取消与保存取消按共用约定验证。 |
| 输出 | 默认容器名 `hd2-repatched-mod.zip`；内部沿用输入 Patch 主文件名，并写 TOC/GPU/stream。未修改的 sidecar 字节保持不变，摘要报告 updated/already-current/removed/converted/refreshed 和 warnings。 | 构建 Blob ZIP 并触发下载。 | 流式写入临时 ZIP，再提交到选择路径。 | 对 `drop/keep` fixture 比较三项文件 hash 和完整摘要；未改 sidecar 必须逐字节相同。 |

## 普通合并

| 维度 | 期望行为 | 目前 Web | 目前桌面 | 可执行验收项 |
| --- | --- | --- | --- | --- |
| 输入 | 一次导入可产生多个 Patch 记录；每条必须有主文件，sidecar 可选但必须满足 TOC 范围。记录顺序决定覆盖优先级，后面的资源覆盖前面的资源；同一次提交的重复角色报错。 | 文件选择和拖放可按文件名生成多条记录，支持大小写后缀；拒绝不支持的主文件名、孤立 sidecar 和重复角色。 | 每次选择经 `describePatch` 只生成一条记录；目录或选择内多个主文件会被拒绝；没有共享拖放入口。 | 对两端规范化入口提交两个 Patch、同名不同批次、大小写、孤立 sidecar、重复角色；断言记录顺序、身份及错误结构一致。调换记录顺序后只允许冲突资源结果改变。 |
| 默认参数 | 输出 Patch 名默认取首条导入记录的主文件名，用户可修改。传给引擎前去掉首尾空格；只接受不含目录的主文件名，不能以 sidecar 后缀结束。 | 首条记录自动填入输出名；固定下载容器名 `hd2-merged-mod.zip`。 | 同样自动填入输出名；保存对话框默认 `hd2-merged-mod.zip`。 | 导入首条记录后断言默认值；空白、`../x`、`x.stream`、合法 patch 名分别覆盖 UI 阻止和 Rust 校验。 |
| 错误与取消 | 输入、解析、sidecar、输出名、引擎、输出失败映射到统一合并错误码；取消不显示失败。 | `cancellable=false`；错误展示只可靠处理 `Error`，非 Error 会字符串化。WASM `merge_patches` 的回退码与合并语义不完整。 | `cancellable=true`；Rust 使用 `merge.failed`，但当前共享 `TaskErrorCode` 没有该成员，结构化对象可能显示为 `[object Object]`。 | 添加 `merge.failed` 契约测试；分别抛出 JS Error、IPC 对象、取消错误，断言标题、正文和诊断；取消后不下载、不提交文件。 |
| 输出 | ZIP 内含用户指定名称的 TOC/GPU/stream；相同 `(type_id,file_id)` 后者覆盖前者；相同内容重复项计入 duplicate，不计 conflict。摘要按输入顺序列出每个来源和总资源、冲突、重复、元数据修复数。 | 内存读取全部输入，返回完整 PatchBytes，再构建 ZIP。 | 逐条加载后写入用户选择的 ZIP 路径。 | 小 fixture 覆盖唯一资源、相同重复和不同内容冲突；解包后逐项比较字节与归一化摘要，来源顺序必须与记录顺序一致。 |

## 头部合并

| 维度 | 期望行为 | 目前 Web | 目前桌面 | 可执行验收项 |
| --- | --- | --- | --- | --- |
| 输入 | 一次可导入多个 Patch；从记录中分别选择一个护甲和一个头盔。二者可来自同包或不同包。只有恰好一个候选时自动选择；多个候选必须由用户明确选择。 | 可批量选择或拖放并按文件名分组；候选识别先只读 TOC，实际运行才读取 sidecar。 | 每次只生成一个记录；每次导入已通过 `load_patch` 完整校验，无共享拖放入口。 | 同包、分包、零候选、单候选、多候选均走真实组件事件；断言两端自动选择和阻止原因一致，并在运行前完成同一 sidecar 校验。 |
| 默认参数 | `armorHash`、`helmetHash` 初始为空；每类全局唯一候选时自动填入。保存容器默认 `hd2-head-merged-mod.zip`。 | `cancellable=false`，固定下载名。 | `cancellable=true`，保存对话框使用相同默认名。 | 添加记录和删除记录后断言已有合法选择保留，失效选择重算；唯一候选自动填入，多候选保持为空。 |
| 错误与取消 | 未选择来源、找不到目标 Unit、目标 body variant 没有合并、依赖复制失败、sidecar/输出失败使用统一头部合并错误码；取消不显示失败。 | 错误展示会字符串化普通对象；同步 WASM 运行中无法真正响应按钮取消。 | Rust 当前复用 `migration.failed`；结构化 IPC 对象经过局部展示时可能变成 `[object Object]`。 | 为头部合并建立专用稳定错误码或明确共用码，并在 TS/Rust 边界契约测试中固定；执行取消和保存取消按共用约定验证。 |
| 输出 | 在护甲归档中合并选中头部，覆盖目标 slim/stocky body 的适用 LOD；复制所需依赖并稳定重映射冲突 ID。输出三项 Patch 文件及摘要，包含 merged body/LOD/part、复制数、冲突重映射、跳过项和警告。 | 使用 prepared archive 和 chunk sink 输出 Blob ZIP。 | 当前先序列化完整 PatchBytes，再分块写 ZIP。 | 同包、分包、双体型、不同 LOD、依赖 ID 冲突 fixture 在 buffer/chunk sink 与 Web/desktop 之间比较解包字节和摘要；ZIP 元数据除外。 |

## 代理验收分工

前端代理应把宿主输入先规范化为平台无关记录，并为四种操作接入同一任务与错误展示入口。验收必须从组件事件或应用控制器触发到适配器请求出口，覆盖选择、重新选择、拖放、取消、保存取消和结构化错误；只验证未被页面调用的工具函数不算完成。

Rust 代理应让四种操作消费同一输入校验、计划和输出协议。仓库内的小 fixture 必须覆盖成功、缺失或截断 sidecar、格式错误、覆盖顺序和归一化输出。串行/Rayon、buffer/chunk sink 的结果以解包后的路径、字节、摘要和警告为准。

需要本地游戏安装或外部大 Mod 的 `#[ignore]` 测试只用于补充压力和真实数据验证。CI 中显示 skipped/ignored 不代表对应行为已有覆盖，也不能替代上述仓库内确定性 fixture。
